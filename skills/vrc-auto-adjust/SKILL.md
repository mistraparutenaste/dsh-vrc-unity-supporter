# 試して直すループ

ユーザーの言葉（「ふわっと」「食い込まないように」「もう少し上」）を、測れる目標に置き換え、
**試す → 測る・見る → 直す** を決まった回数だけくり返してから、結果を見せて適用の確認を取る。

## 決まり（すべてのループで守る）

1. **回数**：1 つの依頼につき 4 回まで（ユーザーが許せば 8 回まで）。届かなければ、そこまでで一番良い案と、届かなかった理由を伝える。
2. **範囲**：一度に動かす量と、動かしてよい範囲は下の表のとおり。範囲の端に来たら止めて伝える。
3. **保存しない**：試す間はシーンを保存しない（`simulate` / `capture` / `tune` はメモリ上で試す）。適用は、最後に結果を見せてから、いつもの preview → 確認 → apply で行う。
4. **見せるもの**：最初と最後の数値（または画像）を並べる。何を何回試したかも短く伝える。
5. **ユーザーの判断が要るもの**：好み（かわいいか、自然か）、作者の表情やギミックを止めること、性能ランクが下がること。これらは勝手に決めない。

| 対象 | 1 回に動かす量 | 動かしてよい範囲 | 判定 |
|---|---|---|---|
| 揺れ物の値 | `tune` が決める（pull ×0.75、spring +0.15 など） | 各値 0〜0.9、角度の上限は 90° まで | `simulate` の数値 |
| 揺れ物のコライダー | 太さ +1 cm | 脚の太さ + 4 cm まで | `legDepth` |
| 小物の位置・向き | 1〜2 cm、5° | 最初から ±10 cm、±30° | 撮影の画像 |
| 小物の大きさ | ×0.95〜1.05 | ×0.7〜1.4 | 撮影の画像 |
| ビューポイント | 0.5 cm | 自動の位置から ±3 cm | 撮影の赤い印 |

## 揺れ物（数値で自動）

```powershell
$pb = '<pkg>\tools\unity_physbone.py'
python -B $pb tune --project '<project>' --scene 'Assets/Avatar.unity' --avatar 'Avatar' --goal softer --target 'AvatarDynamics/PB/Hair/Hair_back'
python -B $pb tune ... --goal no-clip --target '<スカートの PhysBone>' --target '<もう 1 つ>'
python -B $pb tune ... --goal stiffer --recipe SoftHair            # 既存のレシピから始める（元のレシピは変えない）
```

| 言葉 | `--goal` | 目標 |
|---|---|---|
| ふわっと、もっと揺れて、髪がなびくように | `softer` | 振れが 1.25 倍以上、揺れが 0.25〜1.5 秒で収まる |
| 硬く、揺れすぎ、暴れる | `stiffer` | 振れが 0.75 倍以下、収まる時間が延びない |
| 脚を貫通する、食い込む、座るとめり込む | `no-clip` | 太もも・すねへの食い込みが 1 cm 以下 |

- `--target` は `list` の `target` か `root`。複数指定できる。
- 1 段ごとに Unity を Play モードで動かす（30 秒〜1 分）。既定で 4 段まで（`--iterations`、最大 8）。
- `softer` は 1 段目で値を、2 段目から角度の上限と `immobile` もゆるめる。揺れが 1.5 秒を過ぎても収まらなくなったら、1 つ前の段で止める。
- `no-clip` は 1 段目で太もも、3 段目からすねにもカプセルを足し、1 段ごとに 1 cm 太くする。
- 結果：`history`（段ごとの値と数値）、`met`（目標に届いたか）、`recipe`（書き出したレシピ。既定の名前は `<元のレシピ>_<goal>` か `Tuned_<goal>`）、`image`（最後の動きの画像）。
- 書き出したレシピは、`vrc-physbone` の preview → 確認 → apply で適用する。

## 表情（再生テストで判定）

```powershell
python -B '<pkg>\tools\unity_playback.py' test --project '<project>' --scene 'Assets/Avatar.unity' --avatar 'Avatar' --auto
```

- `summary.failedStates`：レシピの値が出ていない状態。`layerStates` で DSH のレイヤーがどのステートにいるかを見て、原因を探す。
- `mixing[]`：作者の表情が混ざった状態と、混ざったシェイプキー（`mixedShapes`）。直すには、そのジェスチャーのエントリにそれらのシェイプキーを `0` で足す。
  足したシェイプキーは、作者のほかのジェスチャーでも動かなくなる。これはユーザーの判断なので、先に伝えて了承を得る。
- 表情の再生テストは保存したシーンを読む。直したら apply して、もう一度テストする（回数は上の決まりに数える）。

## 小物・ビューポイント（画像で判断）

`unity_accessory.py capture`、`unity_proportion.py capture` の画像を見て、レシピの `position` / `rotation` / `scale`、`view` を直し、もう一度撮る。

- 1 回の撮影ごとに、何がずれているか（例：「帽子が 2 cm 前にずれて、額に埋まっている」）を言葉にしてから直す。
- 頭に載せる汎用の帽子は、まず `scale: "auto"` で合わせてから、細かく直す。
- 画像を読めないときは、このループはしない。撮影のパスを伝えて、ユーザーに見てもらう。
